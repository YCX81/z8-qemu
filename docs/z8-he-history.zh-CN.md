# 历史 HE 保留：独立生命周期验证

[English](z8-he-history.md)

本实验在有界 ARM64 执行器中运行
[NikonFirmwarePatch 的 85c7538 版本](https://github.com/XinmiaoZhao/NikonFirmwarePatch/tree/85c7538724e8b9972918aeb3726c033bd54af90c)
三个钩子，不改现有 QEMU 模型、无损研究工作树或外部源码，不生成相机升级包。
[数值收据](verification/he-history-20261017.json)属于受控执行证据，不是实机验收。

## 功能范围

按作者实现的边界：FX、C15/C30、原厂预拍设置最长一秒；选中历史帧同时保留
JPEG 与 HE NEF。全按后的连拍仍只有 JPEG，没有 HE★、无损 NEF、RAW-only
或即时照片库登记。作者报告正常关开机后刷新 RAW 回放标识，本实验未独立复验。

外部源码为 GPL-3.0-only，本仓库不复制它。这里只发布独立编写的服务执行器、
合成结构生成器及测试。运行者另行提供固定版本的外部源码；原厂 C3.11 模块为可选
本地输入。源码和输入均检查哈希，不下载或公开 Nikon 固件。

## 三个钩子的所有权

| 边界 | 本次执行内容 | 前提 |
|---|---|---|
| P1 `0x40f6fe90` | 在扩大的 E 分配尾部绑定 R/E/M、历史序号及配置，并生成 CRC；保留原 submit 返回值 | 确为历史帧，分配容量包含尾部 |
| P2 `0x40ea915c` | 选中时保留 R+0x748 的 E，否则释放并清零 | 同一帧只执行一次，保留期间不得复用该存储 |
| P3 `0x40ea367c` | 匹配 JPEG 的 M 和照片编号，构造 NEF 元数据，从对应帧 DMA 原样写入 payload，释放 E 与 JPEG 头 | 同一头资源只回调一次，primary writer 服务串行 |
| 原清理 `0x40ea44d0` | 提供原模块时实际执行释放并清零 R+0x748 的原指令 | 本夹具的其他 R 资源指针为零，底层分配器释放服务仍是模型 |

另行解析输出头，检查 8280×5520、14-bit 标签、压缩标识、完整 payload 长度和
连续 DMA 的父帧地址。合成 payload **不是合法 HE 图像**，这些检查不能证明 HE
解码、像质或动态范围。

## 已复现的行为

本地收据有 43 个场景及两个故意破坏的构建对照。覆盖 C15 的 5/15 帧、C30 的
9/30 帧、逆序完成、最近 N 帧、配置缺失/损坏/双卡歧义、排除拍后帧、过期或损坏
记录、JPEG 未到达、分配失败、短写、创建/关闭/改名失败、协作预算超限、六轮完成后
再次触发、两个保留帧交错完成，以及在明确的调用方分配合同下，完成和取消后复用相同
R/E 地址。每份成功输出均检查 RAW 标签与逐帧 DMA 绑定。

以下五个场景刻意复现限制或“只调用一次”的前提，并未当作安全成功：

- P1 在保留后重入，会覆盖保留状态，P3 跳过 NEF；E 仍可由 R 清理释放。
- 同一 E 重复执行 P2，会在 writer 之前提前释放。
- 同一头资源重复执行 P3，会再次尝试释放头资源；另一个文件携带独立头资源时，
  不会再次释放已经消费的 E。
- 文件系统调用不返回时，协作预算无法中断；资源仍处于在途状态，不会自动清理。
- 连停止标记也创建失败时，故障没有持久锁存，下一轮仍可能重试。

这些属于对抗调度和故障注入，**没有证明原厂调度器实际会重复投递钩子，也不是相机
已出现这些故障的证据**。没有修改上游行为以使测试通过。报告 `PASS` 表示符合预期的
行为被复现，包括上述限制，不代表每个场景都安全。

两个故意破坏的构建使用上游自带的 `NEG_READ_PAYLOAD`、`NEG_NO_CLEAN` 开关。
执行器分别拒绝 CPU 读取不透明 HE payload，以及 DMA 读取未清理的 CPU 元数据。
未知释放、未知服务及执行预算耗尽都失败停止，不返回假成功。

## 复现

需要 Python 3.12+、支持 AArch64 的 Clang 和可选依赖：

```sh
python -m pip install -r requirements-he-history.txt
git clone https://github.com/XinmiaoZhao/NikonFirmwarePatch.git .local/he-source
git -C .local/he-source checkout --detach 85c7538724e8b9972918aeb3726c033bd54af90c
python -B tools/z8_he_history_audit.py \
  --source .local/he-source --compiler clang-18 \
  --report .local/he-history.json
```

追加 `--stock-main /absolute/path/to/your/z8-c311-main.bin` 可执行原清理指令；只接受
配置中固定的完整 SHA。未提供时，清理场景使用明确标识的合同替身，报告会写明没有
执行原清理。每次报告必须使用新路径，不覆盖旧结果。

本地使用 Ubuntu Clang 18.1.3、Unicorn 2.1.4，编译结果与上游审阅的 Apple Clang 21
配方不一致，报告保留 `reviewed_machine_code_match=false`。验证的是固定源码的
本地构建；没有绕过上游升级包工具的编译指纹检查，也不能认定等价验收了它的精确字节。

普通测试集运行不需要固件的夹具检查。显式设置 `Z8_HE_SOURCE`、`Z8_HE_CLANG` 才会
运行外部钩子；独立 CI 作业读取固定外部版本，在没有 Nikon 固件的条件下执行场景。
本执行器不需要完整 QEMU 构建。

## 仍缺的证据

需要原生调度轨迹确认每代 E 的钩子只调用一次、分配与归还代际、writer 在途取消及
池背压。合成交错不等于忙卡或并发 RTOS 验证。实际文件系统关闭、阻塞恢复、双卡、
耗尽及掉电未建模；关闭失败注入会移除模型句柄，不能证明实体文件系统已释放句柄。

本轮没有安装三个钩子后的完整 QEMU 启动、合法历史 HE 样本独立解码、物理节拍或
真机证据。原清理执行只覆盖 R+0x748，不代表整个原生资源图验收。继续与现有无损
政策链隔离：两方都改 text-copy loader，单独窗口匹配不能准入组合镜像。后续集成
必须独立验证输入、搬运范围、分配和生命周期。先不刷机。
