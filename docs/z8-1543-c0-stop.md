# Z8 C0 control-stop experiment

The default-off `z8-1543-c0-stop-model` addresses a control acknowledgement, not an image producer or RAW pre-release implementation. It is scoped to the original C3.11 C0 ring stop. No camera update is generated. Read-only state is available as `z8-1543-c0-stop-state`.

The matched HALF10 diagnostic observed service index0 (native field a03b71264=0), service a02f26460, device ID1f9/base15420000, and request+70=1. Before the original request, C0 at15431000 was active with control101, mask29 and pending0. The worker accepted software flag2, called40c25f2c ->40c26818 and wrote100 to C0+4. Its lower ANY-mask2c wait then returned false with flags0 twice. The final original42200021 report returned result4. The initial report memory already contained4 and is not used as this operation's result.

The original status+14 bit5 -> IRQ6a -> W1C -> event41070030 ->40cb7200 path sets service flag4 for that ring request. The model supplies only the device's control-stop cause after quiescing its synchronous pixel writer. It never writes service flags, CPU state, firmware bytes or report results.

Admission requires Z8 at machine creation with existing1543 control and raw-pipeline IRQ prerequisites. Only a ready, active, non-held C0 whose original latched/current control is101 may execute100 as the new acknowledgement transaction. The latched interrupt mask must be29; current masking remains independent. The exact command retires active state and sets C0 pending20 once. Existing pixel/refill bits1/8 remain owned by their original producers. New start before W1C of the owned stop cause fails closed; repeated or inactive stops do not create new completion events. Mode2 while inactive remains configuration retention. An active held-mode stop remains unsupported by this narrow opt-in. C1's existing bit5 after six actual output writes is untouched.

All current pixel writes execute synchronously in a device callback. The control model therefore acknowledges after active/held are cleared, without a fabricated frame delay. Masked status remains pending; normal unmask and W1C use the existing shared IRQ aggregation. This is a functional timing assumption, not measured EXPEED timing.

The original binary first failed the actual QTest stop-bit assertion. Its separate positive preview test produced real RAM writes before stopping. The changed binary passes22 cases in normal and optimization mode: flag-off/Z9/dependency boundaries, exact transition, inactive/repeated/held/unsupported controls, actual masked/unmasked GIC input transitions and W1C, preserved real preview frame/refill causes, shared A0 IRQ ownership, new generations after acknowledgement, C1/C2 control isolation, and creation-only configuration. The DMA stop tests first produce1 or3 actual preview frames and changed RAM, then stop, acknowledge and advance virtual time; output RAM and frame counts remain unchanged. They do not use a zero-to-zero counter comparison as a DMA test.

The existing32 D980 tests, including ordinary actual RAM output, and29 F04F transaction tests also pass on the new binary under optimization. C1 coverage here is control/state isolation; the entire C1 pixel-producing NEF workflow was not rerun on this binary. Test-driver coverage is reported separately from model C coverage. Actual matched HALF11 has not been run.
