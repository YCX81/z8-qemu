# Z8 串行外设配置保持

`z8-serial5-config-model=on` 是默认关闭的调试选项，只能在创建 `nikon-z8-bringup` 且启用 `bootstrap-fixtures` 时设置。模型只保持五个通道的四个配置字中的指定字段；不实现FIFO、DMA、传输完成或声音播放。

普通RAW的时序输入修正后，C10在 `0x40c1784c` 首次读取通道0的 `0x0e200110` 时停止。原函数 `0x40c17824` 对以下字段做读改写，并在RAM描述符中保存两个回调；它本身不是完成等待环。

| 通道基址 | 偏移 | 可写位 |
|---|---|---|
| `0x0e200100 + channel * 0x100`，channel=0..4 | `0x10` | `0xfc0c0000` |
| 同上 | `0x40` | `0x00000101` |
| 同上 | `0x44` | `0x0000ffff` |
| 同上 | `0x48` | `0x0000ffff` |

实际C10参数是mode3、bit8=0、低半字1200。模型的初始0是明确的功能仿真假设，不是从未知访问返回的占位0推导出硬件复位值。读改写只改变对应通道和字段；保留其它位、宽度、邻居及未建模控制路径的严格停止行为。

原调用者 `0x40c7d1b4` 所属dispatcher由 `0x40c7cf00` 注册；同一服务初始化使用 `AudSvAl1`、`AudSvAl2` 名称，支持其音频服务关联。不能因此把寄存器保持称为Bayer传输实现，也不据此确定物理串行协议或外接芯片。可继续通过原菜单的快门声音设置研究是否能避开这条音频依赖。

2026-10-13 的 RAW28 实验在原 `0x40c178e4` 读取 `0x0e200110` 时停止。所属原函数 `0x40c178bc` 随后读取 `+0x40/+0x44`，保留模式位以外的原值、只更新 `+0x40` bit0 和 `+0x44` 低16位，并保存另两个回调。此路径与既有 `0x40c17824` 的 bit8/`+0x48` 配置分别保持。RAW28使用独立实验程序调整格式和高速处理类别，此处仅为配置路径证据，尚无历史RAW图像验收。

RAW29在补齐上述字段后越过旧停止点，随后于 `0x40c18428` 写入 `0x0e200110=0xd0000000` 时停止。原 `0x40c183e4` 独立更新该字的 bit26、bit28、bit18；配对函数 `0x40c18368` 更新 bit27、bit29、bit19。掩码仅据这些明确的原位域扩展，bit24/25和其它空隙继续拒绝。条件分支仍由原程序执行，模型只保留最终写入值；不据这些写入创造状态、FIFO数据、DMA或完成中断。

后续语义复核确认，RAW28/29试探的类别1由照片/视频属性`218c`的视频分支选择，并非已证实的照片RAW处理路线；该类别改动已撤回作为RAW预拍方案。上述原位域及模型回归证据仍有效，但只能说明外设配置保持，不能把这两轮称为RAW照片数据通路成功。

新增测试覆盖五通道隔离、bit0与bit8互不覆盖、`+0x44/+0x48` 独立保持及原接口拒绝边界。QEMU会将从`+0x44`开始的未对齐64位QTest操作拆成两个32位回调；测试单独记录这一行为，不把它当作设备接受一个64位原生寄存器访问，也不承诺整组原子性。

`+8` 既有配置保持原样，其中传输使能位12/13继续拒绝；FIFO及其它未建模状态保持严格边界。本选项不会增加DMA、完成中断、OS事件、NEF或相机文件。

初始三字段版本的本地QEMU构建SHA-256为 `0ff25311649a43d8691d60e5da02160cf71ea68d0d2725df0ad7f06f49ddce27`，当时46项实际QTest通过。该历史结果不包含本次新增字段。

2026-10-13 扩展版本的隔离构建SHA-256为 `bdde447bf0dbd96779230623f818da8a7004a77209f8bb4cd3af1b9d549644be`。55项实际QTest在普通及优化模式分别通过，32项既有D980控制及实际RAM输出回归通过；所有测试进程关闭。旧0264二进制在新增字段的正例上失败，负例材料单独保留。测试使用自编零kernel，不执行尼康固件；原RAW预拍程序接入和历史图像验收另行记录。

```sh
python -O tests/test_z8_serial5_config.py \
  --qemu /path/to/qemu-system-aarch64 \
  --output .local/serial5-qtest-01
```

在拍摄研究中，应将该属性显式加入自行保存的捕获属性配置文件，并记录文件哈希及启用理由；默认捕获配方没有自动开启它。当前运行和剩余条件见[RAW运行对照](z8-raw-runtime.md)。
