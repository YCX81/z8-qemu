# RAW 预拍：时序输入与格式政策对照

2026年10月12日。以下均为固定 Z8 C3.11 在本地 QEMU 中的有界实验。**普通触发后 NEF 已通过独立解码及完整像素比对；触发前历史帧闭环仍未完成**。原 MAIN 保持不变；只有标明的C15政策对照运行独立派生程序，未生成更新容器或刷机。

## 普通 RAW 的等待计数

原 RAW + Lossless 菜单与触发路径已经实跑。此前并非停在 CCOMP 应答：原应答、GPIO、任务转发及 flag8 路径均继续执行。真正的大等待数来自原时序计算，不能靠强制完成或跳转消除。

负对照 C09 在原 `0x41172528` 直接取得：系数 W20=0，除法分子600599、分母600600、完整商0。分母非零，也不是商的低16位溢出。随后同一输入对象的 `+0x128/+0x12e` 变为65535，上游加1得到 `acb0=65536`，最终约5.4万次等待。

实际输入为 mode0、`+0x174=1`、sub3。原选择函数因此取表索引1；原资源0x5c已搬至RAM `0xa155d78c0`，读系数的相对位置为 `0xe3022`。原仿真只补充了索引0和13的sub3系数，缺少索引1。

正对照 C10 仅新增一个外部ROM表项：`0x47f63022` 的16位值为1200。该值沿用现有虚拟行时序假设，**不是恢复的原厂校准**。原读取现场实际核对了 selector1、sub3、X21=`0xa156ba8e2`，以及ROM和搬运后RAM均为1200；没有改实时RAM或固件算术。

| 原运行数值 | 缺表项 C09 | 单表项对照 C10 |
|---|---:|---:|
| W20时序系数 | 0 | 1200 |
| 除法分子 / 分母 | 600599 / 600600 | 3464999 / 600600 |
| 原完整商 | 0 | 5 |
| 输入半字+0x128 | 65535 | 4 |
| 原acb0 | 65536 | 5 |
| 原CSEQ计数 | 约54300 | 5，初始剩余4 |

修复这项仿真输入后，原流程跨过旧调度卡点，首个新未知访问为 CPU1 在 `0x40c1784c` 读取 `0x0e200110`。原调用者 `0x40c7d1b4` 调用串行外设配置函数；该函数对偏移+0x10的高2位、+0x40的bit8和+0x48的低16位做读改写，不是完成等待环。现有模型尚未保持这三个配置字段。未知访问返回的占位0不是硬件复位值证据，也不能用它声明通信完成。

C10在首个未知访问后停止；单张传感器请求、RAW151和JPEG后处理仍为0，没有NEF。此结果证明时序输入修正有效，未证明整个拍摄完成。

## C11：普通 NEF 正对照

此轮使用原MAIN，原UI关闭快门声音、选择RAW与Lossless，并保持正常S模式。外部时序系数为上述1200，同时显式开启[有限串行配置模型](z8-serial5-config.md)。137个接点及返回全部匹配，程序正常退出、独占QEMU关闭，原输入和驱动哈希未变；拍后恢复实时取景。

从停止的虚拟卡完整导出 `DCIM/100NCZ_8/DSC_0001.NEF`，文件80790528字节，SHA-256为 `d3a59913fecf887036ba88aa6f4c3abccdfaa80b9577adca3629f9816201959a`。目录与exFAT检查通过，没有由宿主生成或替换NEF。

- rawpy0.27.1 / LibRaw0.22.1解码得到8280×5520个14位样本；**全部45,705,600个样本与实际D980/RAW151快照一致，差异0，帧ID1及反码正确**。
- NEF的RAW strip共80,017,920字节，连同行padding与实际RAW151 packed输出哈希相同。
- 三个内嵌JPEG分别为160×120、8256×5504、1620×1080，均可解码；本轮没有保存独立JPEG编码器完整快照，不宣称该层逐字节比较。
- 原RAW步骤、NEF tag和writer均实际到达，writer返回0；251个NVMe请求、1141条事件、190次普通写入全部完成并交付CQ，无失败或挂起。NEF整个卡范围均被writer调用后的成功写入覆盖。

完整数值与证据界线见[单文件收据](verification/raw-single-20261012.json)。实际DMA时间为190696949981ns，晚于原GPIO全按处理190664648640ns和MCU全按消费190664851288ns，因此是**触发后帧**。两条触发路线都记录，未证明其中一条是唯一触发者。

单帧外设模型的requests/frames仍为0，这帧由已启用的周期stream模型提供；不能把有效NEF外推成单帧硬件协议验证。原pool分配和完整缓冲寿命、逐文件writer对象身份、多帧保留/顺序仍未闭合。该组合对照也没有分别证明关闭声音与配置模型各自是否充分；稀疏音频观察点未命中不代表全运行从未有音频活动。菜单的Lossless选择和功能性packed14输出，不等于真实尼康压缩或ISP算法已恢复。

## C15 预拍的资源与缓冲

原UI已选择C15、d3预拍窗口0.3秒，实际释放模式6、容量5。HALF-only负对照02的原处理模式14经原表映射到资源索引槽15；缺项0经32位减1形成越界。直接异常PC=`0x41170d84`、FAR=`0x2a156b2806`、ESR=`0x96000005`，保存的寻址寄存器与原指令精确闭合。

对照03仅在外部ROM `0x47f5af4f` 补1字节记录号1。原LDRB实测为1，原读取基址回到有效资源对象，旧下溢消除。记录1依旧是已有中性仿真输入假设，32字节记录未修改、系数未恢复。

随后原固件写 `0x150c0008=0xff00` 被现有D980模型拒绝。掩码本身合法；实际配置目标是内部流端口 `0xe0000000`，不是已分配的RAM。D980同时使用控制+0x118=3和高度低16位2，与当前普通RAW内存写入模型不同。没有将内部端口映成RAM，也没有放宽校验或制造像素完成。

## NEF 政策与早期数据流

对照04在03基础上仅改独立程序副本的一条4字节政策指令：`0x40edec78` 强制选择格式1。实验期间它影响全部格式候选，**不是最终的C15专用开关**。20组Unicorn对照确认仅目标格式寄存器改变，其它通用寄存器、条件标志和PC一致。这些指令测试不计为拍摄验收。

```text
原 MAIN SHA-256
2b43a31c9de838f84b12416de4348a7004e65be07f853ec56ec2b10f3a8e3853
实际执行的政策副本 SHA-256
fb11ccb2ae3fb27931cfcf3bc0ab90f11b37757cb8222dfcbf20b40258c8ee25
```

原绑定仍从原MAIN核对，实际kernel路径、派生hash和政策差异另行记录；不是运行时改PC、任务标志或完成结果。所有原/派生文件前后hash一致，独占QEMU已停止。

| 现场字段 | 原JPEG政策03 | 强制NEF政策04 |
|---|---|---|
| 格式候选 / 有效门控 / 结果 | 3 / 0 / 3 | 3 / 0 / 1 |
| 实际拍摄info+0x3c8 | 本次未直接采样 | 1，已直接读取 |
| D980源路线 | 内部FIFO | route mode11，四槽仍为内部FIFO |
| D980完成帧 / 历史队列暂停样本 | 0 / 52次均空 | 0 / 52次均空 |
| 首个未知访问 | `0x150c0008=0xff00` | 相同 |

原生产链也说明这不是丢失了一个RAM指针：`0x40e8d794` 按job+0x10的类型11选择helper ID0x26，随后 `0x40eb60e8 → 0x40eb68e4` 明确构造内部端口并写入request+0x140四个源地址。这个源地址生成分支没有Bayer RAM分配或引用计数；这不代表整个下游没有其它RAM生产者。格式1已进入info，却没有改变这条job类型与源路线。

本实验在尚未建模的内部流启动处就已停止，**尚未证明RAW输出或历史缓存成立**。它不能排除内部Bayer流的下游原consumer会分配RAW输出，也不能据此判断在完整硬件模型或实体相机中是否只需修改门控。本项目还须追到内部流消费者、有效RAM输出、保留、转换、提交及释放。

## 剩余验收

1. 普通Z8 NEF正对照已通过；继续取得实际allocator、逐job身份和缓冲寿命证据，不把周期源结果当作历史帧。
2. 为高速路径确定内部Bayer流消费者、实际RAM输出和所有权，不先假设必须由D980直接写RAM；保留历史期间不得提前复用，不能以内部端口地址替代像素快照。
3. 关联同一帧的格式、历史队列、RAW后处理、NEF writer及实际NVMe写入。
4. 至少两帧触发前历史加一帧触发后，核对全部文件的时间、FIFO顺序、数量和LibRaw解码的完整像素，再检验取消与重复拍摄的释放行为。

两项外部资源现有[显式实验选项](z8-capture-resources.md)，公开接入已过契约测试，不能自动沿用原私有运行的动态验证。独立NEF政策副本仍为私有研究配方。另有默认关闭的[串行配置保持模型](z8-serial5-config.md)，仅覆盖已确认字段。工具与限制见[诊断驱动](z8-capture-probe.md)、[多帧审核器](z8-precapture-audit.md)和[TODO](TODO.md)；这些都不是已完成的RAW预拍功能。
