## 可复用的具体实现

`qemu/nikon-z8-input-pair.h` 依据参考仓库的 `nikon-z9-pixels.h` 实现 `raw-pipeline-input-pair-model`。六路实际 RAW 派生 Y/UV 内存写入全部成功后，才产生主图像组1的 bit31；保持原 mask、W1C、未确认时禁止复用、复位取消所有权的机制。默认关闭，实例化后不能改动，需要已有 RAW 管线。

移植同时加入六个目标区域之间的交叉重叠检查，在任何写入之前拒绝重叠输出。该检查仅作用于显式开启此实验的运行，未改变原有默认配置。GPL 声明和上游出处保留在头文件中。

Z8 C3.11 的消费链已用本地原始指令和运行观察核对：`410b0ce8` 检查 payload+4 bit31，`410b0fc4` 分派 `04220013`，`40e8b9cc` 在原状态条件满足时由 `40e8ba6c` 设置自身事件。模型没有写任务标志、OS 返回值或成功回调。`zr-ref-pair-repeat02` 实际观察到事件值 `04220013` 和原函数设置 `80000`，最终612次完成由原 W1C 全部确认。

这仍是组合 ISP 的功能假设：bit31 对应的准确硅片阶段和物理时序没有证明，当前真实内存写入来自已有 C0 预览管线。它不等于 C1 视频图像输入、编码帧或文件写入。

## 哪些实现不能直接搬入

| 参考实现 | Z8 当前判断 |
| --- | --- |
| 输入完成与独立确认 | 已作为上述显式实验适配，原回调确实消费，但未解除完整流程阻塞。 |
| `engine151-active-program-model` | 可以借鉴活动配置与下一次提交分离的设计。Z8 已锁存配置；本轮 VIDEO 快照中 ISP 实例本身已 inactive，不能把这一状态解释为仅需增加参数位图锁存。 |
| `video-secondary-sensor-model`、`video-primary-boundaries-model` | 参考实现要求已接纳的内部视频输入、C1 活动状态和完整六路输出。Z8 尚未具备这条数据链，不能仅复制完成位。 |
| WLVR/zlib 内部 RAW 传输、x265/x264 后端 | 是明确标注的功能替代，不能称为原厂 Nikon/RED 编码；还需按 Z8 描述符、格式和生命周期适配。 |
| ZR 取景方向与按键 | 其配方默认横屏，VIDEO 使用半按加全按启动；Z8 保留本机姿态与录像键绑定，不能直接复制 ZR MCU/任务地址。 |
| 文件方向快照 | 本轮检查的 ZR 工具和说明没有提供可直接复用的 `tkhd` 方向锁定实现。继续使用独立的 Z30 设计参考，等待 Z8 实际录像对象与文件。 |

具体不匹配例子：本轮 Z8 VIDEO 快照的 ISP1 锁存尺寸为1296×864，`430/434=3904`、`480/484=2624`，实例已经停止；ZR 的 secondary 接纳规则要求活动的16:9配置、行宽等于 `width*3`、相应源门控及完整的内部端口关系。共享 EXPEED7 不代表这些配置可直接互换。

- 新测试先在旧构建以“缺少属性”失败；适配后6组通过，覆盖六路实际 RAM、掩码/中断、确认、禁止提前复用、关闭源、坏末路、跨通道重叠、复位取消与运行期不可变。首次复位夹具漏发保持命令，补齐既有协议后通过，没有放宽模型。
- 同一最终构建运行上述6组、源完成3组、输入时钟2组、C0/C1停止15组，共26组通过。完整 Python 测试386项通过。
- `zr-ref-pair-native01` 的505次完成全部确认，首轮回到照片界面；同构建关闭选项的 `zr-ref-pair-off02` 也回到照片界面。因此单次截图改善不能归因于新增模型。
- `zr-ref-pair-repeat02` 连续第二轮再次出现 Error；`40e98974`、`40e96008`、`40e991b0` 仍观察到失败返回。该轮第二次 MENU 按键只是切换到菜单标签，不能把标为 `menu-return-right` 的截图当成成功退出菜单。
- 上述三张已停止虚拟卡均只读检查通过，只有512字节 `NIKON001.DSC`，没有 MOV/MP4。`error=null` 只表示宿主配方执行完，不表示相机录像成功。
- 随后 `zr-ref-pair-repeat03` 改用原厂半按退出菜单，去除诊断等待断点，完成左右方向各一轮 VIDEO/PHOTO 界面回切和菜单进入/返回。两次照片返回后的实际 RAW 派生帧分别从504增到578、1052增到1126，界面未见 Error；最终1265次完成全部确认。MENU期间抑制掩码为 `20`，返回后为0。这个结果是指定输入序列下的界面/照片取景验证，不能据此声称此前内部超时全部消失或新模型是改善的唯一原因。该轮虚拟卡同样没有录像文件。
