# 共享模型拆分前的分支分类

静态基线：`a97f5df` 的 Git blob，而非含用户改动的工作区。`nikon-z9-lab.c`
为18,708行、838,193字节；有23处 `nikon-zr-lab` 机型判定。
下面覆盖这23处显式判定，不等于完成全部状态字段、间接调用和运行可达性证明。
本批没有删除代码、重命名QOM接口或修改C模型。

## 23处显式判定

行号固定对应上述基线；后续查找优先使用函数与条件名称。

| 类别 | 基线行号 | 处理原则 |
|---|---|---|
| 仅ZR条件或其准入检查：19处 | 1168、3081、3104、3132、3388、3541、4112、4292、5211、5289、5361、5500、5539、17484、17867、18101、18117、18302、18313 | 包括syscon例外、图形selector、secondary resample、DSI、LCD/I²C、方向输入、bank1和对应setter。先隔离这些条件内的行为，不能删除外围共享函数或状态注册。 |
| 明确包含Z8：2处 | 1179、3982 | `syscon`配置保持和`zr_control1782_word`同时接受Z8；后者虽叫zr，不能按名字删除。 |
| 共享函数内按ZR切换掩码：1处 | 6163 | 保留非ZR的一位掩码分支，分离ZR特例；整个函数不是ZR专用。 |
| 共享初始化中的排除条件：1处 | 17081 | `ccomp_gpio_model`拒绝ZR或缺bootstrap的组合；不能将整条初始化检查当成无用ZR代码删除。 |

当前 `nikon_z9_register_types` 注册Z9和Z8，没有在此注册ZR机器。这两个类型的
ZR正向身份判定为假；含否定判定的参数/属性拒绝分支仍可达，不能当成死代码。
这不足以说明可连同共享函数、状态字段、属性名和错误检查直接删去。
属性仍由共享父类注册，某些状态还参与公共表达式。

## 拆分次序与验证要求

本阶段不再抬高896KiB的发布检查上限。此上限是意外内容检查，不能作为架构质量指标；
把代码机械搬入头文件也不等于降低耦合。

1. 为MMIO入口、图形命令、采集/停止、存储和板级初始化建立调用及状态归属清单，
   指定每组状态由谁初始化、清理和更新中断。先完成上述23处之外的间接依赖分类。
2. 首批只抽出职责闭合的外围实现与相应状态，保持QOM名称、寄存器契约、失败行为、
   源数据和IRQ次序不变；不要同时删ZR分支或改机型策略。
3. 将`unknown_read/write`保留为严格分派入口，子模块明确返回“已处理/未处理”，
   拒绝把未实现访问默认当成功。将`nikon_z9_init`按生命周期分组，保留依赖次序。
4. 每批验证固定上游构建、Z8/Z9注册与拒绝测试、受影响外设QTest、默认关闭等价性；
   运行依赖变动时再做固件回归。历史二进制的通过记录不能自动转给新构建。
5. ZR专用代码的删除另做差异审查，核对共享属性兼容和上游参考用途；本仓库没有ZR
   可运行目标，不能声称在此完成了ZR固件回归。

`nikon-z9-pcie.h` 的Z9命名同样属于继承实现，不是芯片身份的证据。其链路输入
实际还要求端点存在、enable且未reset，仍只是功能假设，未实现PHY/LTSSM。
后续重命名需同步调用者、日志消费者和测试，不能以名字统一代替行为核验。

DesignWare ATU修复保留为独立上游候选：先准备最小复现与固定版本差异，
不在本轮发送上游邮件、提交PR或声称已被上游接受。
