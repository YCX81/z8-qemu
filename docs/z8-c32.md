## C32/C64布局

由 `Layout(32)` / `Layout(64)` 统一定义，默认32，预留每组64；条目地址和编号在两种配置间稳定。

| 项目 | 设计 |
|---|---|
| 条目 | 每条`0x400` bytes；每组固定64条地址空间，保存主参数、附加参数和Flexible Color44。 |
| 选择值 | C1–C9保留原值。新增照片槽为`0x1000 + slot - 1`，视频为`0x2000 + slot - 1`。C32分别为4127、8223。 |
| 显示代码 | C1–C9保留28–36；C10起用`slot + 30`，保留内置代码37–39。 |
| 设置键 | 独立组`0x7c/0x7d`，处理跨256项的边界，不覆盖其他设置组。 |
| 菜单 | 明确的编号解码替代64位位图；C15及以上不再依赖超出bit63的位移。动态生成行、事件、查找表和独立文字；缓存按控件池与槽位管理。 |
| RAM | 从仿真General heap尾部明确保留1 MiB；运行时确认剩余General为10 MiB，相邻Heap起点不变。 |
| 持久化 | schema3、128字节头、双组64条空间，按页补齐为`0x20800` bytes。A/B各占两个连续实验NAND块。先擦目标副本，写两段payload，最后提交header并读回。 |

C32配置只开放64条，未开放的记录必须无效；C64配置开放照片、视频各64条，共128条。完整恢复缓冲与条目区分离。第二块写失败保留旧副本、第二块损坏回退、扫描读错误禁止擦写等均有guest A64测试；CRC32另与标准库独立对照。

后台设置同步、列表发布与GUI各有独立转换路径。扩展了`410ab09c`、`410a8bf4`等路径，防止后台回退Auto；照片、独立视频和继承照片的主菜单指示分别接入新槽号资源。

## 测试与复现

独立副本阶段298项基线和新增Python测试通过，新Python模块的单元与整机合并行覆盖率约96%，不是尼康固件整体指令覆盖率。本次集成回归已增加到318项，C64除原有布局和原生边界测试外，也完成上述四阶段整机仿真；不沿用历史覆盖率宣称新增模块全部达到相同覆盖率。

在本仓库根目录的 Linux/WSL 环境安装 `requirements-c10.txt`。提供身份匹配的本地 MAIN，并用 `tools/make_cmos.py --output /path/to/new-input.raw` 生成合成 Bayer 输入。先通过 `tools/build.py` 构建包含持久 NAND 与空图元处理的本仓库模型；记录真实二进制哈希，不要求其他人的构建字节完全相同。以下路径均需替换为自己的绝对路径；创建一个新的输出父目录，输出子目录不能已存在，创建介质时拒绝覆盖：

```sh
python tools/z8_slots_acceptance.py --slots 32 --phase create --gui photo \
  --firmware .local/firmware/z8-c311-main.bin --qemu /path/to/qemu --raw /path/to/new-input.raw \
  --output /path/to/new-create --media /path/to/new-media.img

python tools/z8_slots_acceptance.py --slots 32 --phase restore --gui photo \
  --firmware .local/firmware/z8-c311-main.bin --qemu /path/to/qemu --raw /path/to/new-input.raw \
  --output /path/to/new-restore --media /path/to/new-media.img \
  --expected /path/to/new-create/expected-records.json
```

视频测试先复制已关闭的上述介质，再用`--phase restore --gui video`与原expected记录运行。随后复制视频已保存介质，用新进程`--gui video-cold`，指向视频运行的expected记录。期望文件只用于核对，启动应用选项来自guest从NAND读取的实际状态。

C64 使用同一入口，将每阶段参数改为 `--slots 64` 并使用另一套新介质和输出目录。不要拿 C32 媒体直接运行 C64；媒体身份绑定容量和派生镜像。视频冷恢复不执行 SAVE，需另核对其媒体文件前后 SHA-256 不变。默认 `Start-Z8.ps1` 不启用任何槽位派生镜像。

历史四阶段标签为 `create01`、`restore01`、`video01`、`video-cold01`。历史原始记录、截图、覆盖率及 `completion.json` 属于本地证据，不随公开源码发布。新的 `result.json` 应同时检查 `slots_complete`、`error`、`input_unchanged`、`owned_qemu_stopped`、`slots_gui` 和逐条记录摘要；GUI 仍须单独审阅槽号、名称、高亮和重入状态。不要仅以一个成功字段接受整次运行。

## 边界

- C64切换需独立派生镜像和新介质。布局稳定，但实验介质严格绑定镜像身份与活动容量，尚无C10→C32或C32→C64无损升级迁移工具。64是当前已验证容量，不是实机硬件上限。
- 当前使用构造NP3和实验文件输入服务。真实云创/NX Studio导出、在线下载、卡片导入及管理/编辑页面、ISP颜色效果尚未验收。
- 槽号为原生文字`C-N`，未复刻原厂相机/FC复合图标。i菜单通过原指令构造测试；本轮整机按键与像素验收针对主菜单选择页。
- RAM与NAND保留是仿真布局，不是实机空闲区域证明；没有生成或使用刷机包。
