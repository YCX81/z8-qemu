# Z8 视频文件方向：原厂基线与独立实验补丁

当前目标包含视频界面旋转和录像文件方向，两者分别验证。现已实现受原 MAIN 身份校验的独立矩阵实验，并通过原始 A64 配置／轨道构造器差分测试。**尚未验证实际 Z8 录像、连续分段或播放器自动转正。** 用户目前没有原始 MOV／MP4 样本，本工作树内也未找到此类样本。

2026-10-14 已接入虚拟文件卡，原固件能够识别容量并建立目录；最新运行尚无 MOV／MP4。已定位的录像封装入口在观察窗口内没有命中，因此未把卡识别或录像按键送达当成文件方向通过。详见[录制链路排查](z8-video-pipeline.md)。本轮未修改矩阵补丁，现有左右方向、两对象隔离、重建头及成功重新配置采样的测试继续通过。

## 参考和适用范围

设计参考是 WonderLantern Z30 的 [`video-rot`](https://github.com/WonderLantern/wonder-lantern-z30/blob/7ab4cec56c6c6a2169b6b1c2ab57a0ed733e135e/docs/video-rotation.md)，本地核对了指定提交的文档、实现和测试：新对象配置成功后采样，在对象自己的视频矩阵槽保存快照，后续视频 `tkhd` 构造使用该快照。共享矩阵、电影头和音轨保持原行为。该项目的实机成功是其记录的用户反馈，文档仍明确原始 MP4 尚未逐字节检查，不能视为本项目的独立复测。

Z30 C1.20 的函数地址、Thumb 指令、对象偏移和姿态编号不能直接用于 Z8。ZR 官方的视频取景／i 菜单旋转行为仅作为 UI 参考；用户提供的 ZR 截图不是 Z8 的屏幕尺寸模板，也不提供文件方向补丁。

## 当前 Z8 C3.11 原始代码证据

原 MAIN 的 SHA256 为 `2b43a31c9de838f84b12416de4348a7004e65be07f853ec56ec2b10f3a8e3853`，只读分析该身份。

| 入口／对象偏移 | 已观察行为 |
|---|---|
| `40cf2880` → `40cf2924` → `40cf3a24` | 创建对象后配置视频参数；目前找到 `3a24` 的一个直接调用点 |
| `40cf3a24` | 成功返回 0，参数错误返回 3；原配置函数不写视频矩阵槽 |
| `40cef3d0` | 视频轨构造器，在栈上生成单位矩阵 |
| `40cefd54..40cefd60` | 将 36 字节矩阵写入对象 `+128`；该视频 `tkhd` 从对象 `+f8` 开始 |
| `40cef168` / 对象 `+b0` | 独立的电影头矩阵 |
| `40cf0880` / 对象 `+338` | 独立的音轨矩阵 |
| `40cefe80` / 对象 `+63c` | 独立的时间码轨矩阵 |

创建入口 `40cf2880` 的直接调用点为 `40345d94`、`403484a4`、`40d18b70`、`40d1b740`，各自的录制模式和分段语义仍待动态确认。创建中的 `40cf3c68` 写入初始 `mdat` 头；视频轨构造器由聚合头函数 `40ceef10` 调用。这再次说明，不能简单把轨道收尾函数当成开始采样的位置。

`tests/test_z8_video_mux.py` 执行原始 A64 配置与四个构造器。在合成对象、明确的缓存一致性地址表和已分配缓冲下，三种原始容器选择值 0/1/2 均成功返回；视频 `tkhd` 长度为 92 字节，矩阵为单位矩阵，宽高为测试输入的 1920×1080。改变界面原始方向值不会改变该构造器的输出。即使预先写入其他矩阵，原视频构造器也会覆盖为单位矩阵。

这些结果验证的是**已定位构造器的原始代码行为**。合成对象没有实际编码样本；0/1/2 的全部格式对应关系、实际录像的其他写入路径及物理左右方向仍需进一步验证，不能据此断言所有真机原片均缺少方向信息。

## 只读原片检查工具

```powershell
python tools/video_track_orientation.py path/to/original.MOV
```

工具逐级读取 `moov/trak/tkhd` 和 `mdia/hdlr`，分别报告电影头、视频轨、音轨及其他轨道的矩阵、版本、轨道 ID 和轨道显示尺寸。支持版本 0/1 和扩展 atom 长度，跳过 `mdat` 编码载荷。它只以只读方式打开文件，不修改标签、不转码。

输出保留全部九个有符号定点数和位移，不把镜像或任意缩放矩阵误称为旋转。`canonical_rotation_degrees` 使用明确列出的标准单位矩阵约定；物理机身左右方向及播放器的角度符号不能仅据这个字段推断。结构依据 [Apple Track atom](https://developer.apple.com/documentation/quicktime-file-format/track_atom) 和 [QuickTime matrices](https://developer.apple.com/documentation/quicktime-file-format/matrices)。

## 实验补丁及验证范围

`tools/z8_video_file_rotation.py` 只改两处原函数范围：参数配置尾部 `40cf3b4c` 的 284 字节，以及视频矩阵初始化 `40cef3f0` 的 32 字节。没有新可执行映射、额外堆对象或额外栈空间。原始文件保持不变，不生成相机升级包。

配置函数保留原校验、错误返回、帧率映射和其余对象字段，只在成功路径读取原厂方向值 `a03228244`，写入该对象独立的 `+128` 矩阵槽。视频轨构造器将快照读入原有栈空间，后续仍由原厂代码封装。它不使用受主菜单／显示开关抑制的有效 UI 方向。当前仅映射已观察的 0/1/2；其他值使用单位矩阵，没有照搬 Z30 的倒置方向编号。

参数配置尾部通过表替换等价的帧率选择分支，保留原错误分支目标 `40cf3b94/98`。测试覆盖 7 个原厂识别帧率及 2 个未识别值、三种对象类型、大文件与辅助字段组合，逐字节比较矩阵之外的对象内容。原校验失败不更新矩阵；两对象保留各自方向，重复构造头不会重新采样，同一对象再次成功配置则重新采样。保存寄存器及原栈平衡亦已检查。

合成输入的左右矩阵分别被只读解析器识别为标准 90°／270°。这验证了字节序和轨道封装；**物理左右方向映射仍未实机核对**。电影头、音轨和时间码矩阵与原始构造器输出相同。编码像素、声音载荷和实际文件关闭尚无运行证据，不能仅凭补丁修改范围声称它们已通过端到端回归。

文件补丁默认关闭，可独立调用 `build_plan(original_main)`，或显式组合：

```python
from z8_orientation_unlock import build_plan
plan = build_plan(original_main, video=True, video_portrait=True,
                  video_file_rotation=True)
```

运行器 `UnlockedGuest` 接受同名 `video_file_rotation=True` 并核对全部加载区间。组合不改变原有 UI 补丁字节，也不解除主菜单限制。文件模块的单独计划不包含任何 UI 修改。

私有 `combined02` 已完成组合镜像启动、视频左右显示和原厂主菜单像素回归，全部加载区间校验通过。该运行没有实际录像文件，也没有把 MCU 录像按键收取当成对象创建或文件生成。
