# 竖屏视频按拍照竖屏布局（2026-11-14 进度）

只供仿真研究。生成的 MAIN 不是升级包，不要写入相机；未在实体相机上验证。

## 内容

| 文件 | 作用 |
|---|---|
| `video_layout_v2.py` | 竖屏视频 274 个控件的坐标规则。有拍照对应控件的直接用拍照竖屏原生坐标，视频独有控件放在拍照空位；画面铺满 480×720。 |
| `histogram_portrait_fix.py` | 竖屏视频直方图修复（原位改写 `0x4041b248..0x4041b2c4`，31 条指令）。 |
| `build_overlay.py` | 把布局写入两张显示器控件表（`0x43a21a70` 与 `+0x1b420` 的副本），再应用直方图修复；每处替换前核对原字节。 |
| `check_overlaps.py`、`check_blank_zone.py` | 静态检查：新增重叠、以及会让视频 OSD 消失的左下区域（x<46，y 570–602）。 |
| `qemu_histogram_lab.py` | 仅供仿真的 `nikon-z9-lab.c` 补丁，用来在 QEMU 中显示实时直方图（含临时绕过，见文件头）。 |
| `driver_*.py` | 私有交互驱动的适配脚本（DISP 键、菜单按键、内存导出）。 |

## 直方图问题的原因

固件 2.10 的“直方图位置”功能在 `0x4041b1a8` 中实现：只要 GUI 画面比例标志（`0xa032cfc70`）为 16:9，就用 `0x42af0dc0` 的预设把直方图移到 `(460,134) (474,254) (142,134) (166,248)` 之一。预设只有横屏坐标，也不判断方向，所以竖屏视频的直方图被放到横屏的 `(474,254)–(636,336)` 并溢出。拍照是 3:2，不经过这一步，因此拍照竖屏位置一直正确。

修复在调用预设前读取有效显示方向（`0x4038d658`），竖屏时跳过预设，保留控件表里的竖屏矩形 `(218,448)–(380,530)`，即拍照竖屏直方图位置。横屏路径不变。把原先 4 条一组的地址构造压缩为 2–3 条，补丁长度与原代码相同。

## 构建

```sh
python3 build_overlay.py --stock z8-c311-main.bin --base v37=v37.main --out OUT
```

`--stock` 必须是原厂 C 3.11 MAIN。本次结果：仿真用 derived MAIN `fb0103ac0e0dc24b…`；在 v37 `e86c7c4a…` 上叠加后为 `4c0a8fab785e9c38…`（相对 v37 改动 3420 字节）。

## 已验证

- QEMU（私有 U-live01 运行时 + `qemu_histogram_lab.py` 补丁副本）：竖屏视频的第一行、FX、画面尺寸、底部曝光行、左右两侧控件与拍照竖屏同位；在 g20 中给显示 2 勾选直方图并按 DISP 后，直方图位于 `(218,448)–(380,530)`。直方图曲线是合成数据。
- 竖屏视频录像启停：沿用前一版布局时通过，本版未重测。
